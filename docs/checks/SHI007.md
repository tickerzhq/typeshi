# SHI007: a conversion that comes out in the wrong unit or off by a power of ten

Every conversion between assets is an amount times a price, divided by a power of ten. Get
the power of ten wrong and the result is off by 100x, or 10^12x; multiply where you should
divide and it isn't even the right asset. Rust and Anchor see `u64 * u64 / u64` either way.

typeshi knows what each number means. An amount ticker is its asset (`ticker SOL = 9;`), and a
price ticker says what it is a price of:

```text
ticker USDC = 6;
ticker SOL = 9;
ticker SOL_USDC = 8 USDC / SOL;   // 8 decimals of USDC per whole SOL
```

From there typeshi follows every `*`, `/`, `checked_mul`, `checked_div` and `10u128.pow(...)`:
an amount of SOL (9 decimals) times a SOL_USDC price (8) is USDC with 17 decimals, and only
dividing by 10^11 makes it a USDC amount (6). When a conversion is written into, added to or
compared with a value whose unit or decimals don't match, it is a compile error, with the
power of ten to fix it.

## Example

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch market {
    ticker USDC = 6;
    ticker SOL = 9;
    ticker SOL_USDC = 8 USDC / SOL;

    frame Market {
        cabal: Pubkey,
        price: SOL_USDC,
        cap: USDC,
    }

    cap_table Quote {
        #[account(has_one = cabal)]
        market: Account<Market>,
        cabal,
    }

    ape fn quote(ctx, amount: SOL) -> W {
        let value: USDC = amount * per_my_last_email!(market.price) / 1_000_000_000;
        trust_me_bro!(value <= per_my_last_email!(market.cap), "over the cap");
        were_so_back!()
    }
}
```

Dividing by SOL's 10^9 forgets the price's own 8 decimals: `value` comes out 100x too big.

Dividing by the price instead of multiplying is a different asset altogether:

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch market {
    ticker USDC = 6;
    ticker SOL = 9;
    ticker SOL_USDC = 8 USDC / SOL;

    frame Market {
        cabal: Pubkey,
        price: SOL_USDC,
    }

    cap_table Quote {
        #[account(has_one = cabal)]
        market: Account<Market>,
        cabal,
    }

    ape fn quote(ctx, amount: SOL) -> W {
        let value: USDC = amount / per_my_last_email!(market.price);
        were_so_back!()
    }
}
```

typeshi says `value` is USDC but gets SOL² per USDC.

## Fix

```shi,pass
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch market {
    ticker USDC = 6;
    ticker SOL = 9;
    ticker SOL_USDC = 8 USDC / SOL;

    frame Market {
        cabal: Pubkey,
        price: SOL_USDC,
        cap: USDC,
    }

    cap_table Quote {
        #[account(has_one = cabal)]
        market: Account<Market>,
        cabal,
    }

    ape fn quote(ctx, amount: SOL) -> W {
        let value: USDC = ((amount as u128) * (per_my_last_email!(market.price) as u128)
            / 10u128.pow(SOL_DECIMALS as u32 + SOL_USDC_DECIMALS as u32 - USDC_DECIMALS as u32)) as u64;
        trust_me_bro!(value <= per_my_last_email!(market.cap), "over the cap");
        were_so_back!()
    }
}
```

Write the power of ten from the `_DECIMALS` constants typeshi generates and it follows them.
`as u128` widens a number without changing what it means, so the usual overflow-safe pattern
is checked too. `x as u64` on a bare amount is still how you say "I am converting on purpose"
(SHI002), and an untyped `u64` anywhere in the expression means typeshi can't know, so it
doesn't guess.

## What it has cost

- **Morpho PAXG/USDC market, 2024-10-13: about $230K borrowed against $350 of PAXG.** The
  market's oracle was set up with the wrong decimals for PAXG (18) and USDC (6), which priced
  PAXG 10^12 times too high
  ([Verichains](https://blog.verichains.io/p/morpho-protocol-market-oracle-price);
  [the market creator's retrospective](https://forum.morpho.org/t/retrospective-paxg-usdc-market-oracle-configuration/891)).
- **Aevo's legacy Ribbon vaults, 2025-12-12: about $2.7M.** An oracle upgrade moved some
  assets to 18-decimal prices while USDC stayed at 8, and the same upgrade let anyone set
  expiry prices; the attacker used both
  ([Halborn](https://www.halborn.com/blog/post/explained-the-aevo-ribbon-finance-hack-december-2025)).
  typeshi catches the first half. The second is an access bug (SHI001's territory).

## What it doesn't catch

Literals other than powers of ten (`* 2`, `* 9_975`) and untyped values make a conversion
unknown, so it isn't checked. It checks that units and decimals line up, not that the price
itself is right, fresh, or from the market you meant: Moonwell's cbETH/ETH-for-USD mix-up is
SHI002's, and a manipulated price is nobody's but your oracle's.
