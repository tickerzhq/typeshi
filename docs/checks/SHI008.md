# SHI008: an agent allowance that is a blank check

An AI agent that pays for things holds a wallet key, and the only thing between a confused or
hijacked agent and an empty wallet is the policy the wallet enforces when it signs. Every
wallet writes that policy differently. Coinbase CDP takes typed JSON rules, Turnkey a condition
language, Privy field conditions, and the amounts are raw integers in the token's smallest
unit, where 250 USDC is `250000000`. One wrong zero is a 10x allowance. And CDP accepts any
operation no rule mentions, while Turnkey and Privy deny it.

typeshi writes the allowance once, in whole units, and compiles it to all three:

```text
pocket_money trader {
    ticker USDC = 6;
    mint USDC = "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v";
    cap USDC = 250;                                         // per transfer, in USDC
    pay USDC => ["7h44au9S2DwyKgAbsepUv459K59cEHBqE9EjSCtC15bi"];
    cap SOL = 0.05;                                         // per transfer, in SOL
    pay SOL => ["4Jcw4u6xczibsADH7hRFT7qdg6iVDFoCQnCB3WFxz6jP"];
    signer = "your-turnkey-user-id";                        // optional
}
```

`typeshi allowance agent.shi --to turnkey` prints the policy, ready for the wallet's API
(`--to cdp`, `--to privy`, or all three without `--to`). The caps come out in the smallest
unit, the recipients as given, and only the programs a transfer needs are allowed.

It refuses to compile an allowance that would sign anything it shouldn't: a token with no cap,
or no recipients (the agent could pay anyone), a cap finer than the token's smallest unit, a
token with no mint, and an address that isn't a 32-byte Solana address, such as an `0x`
address pasted from Ethereum.

## Example

```shi,fail
pocket_money trader {
    ticker USDC = 6;
    mint USDC = "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v";
    pay USDC => ["7h44au9S2DwyKgAbsepUv459K59cEHBqE9EjSCtC15bi"];
}
```

`USDC` has no cap: every wallet would let the agent send the whole balance in one transfer.

```shi,fail
pocket_money trader {
    ticker USDC = 6;
    mint USDC = "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v";
    cap USDC = 250;
    pay USDC => ["0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"];
}
```

That recipient is an Ethereum address. On Solana it matches nothing, or in a looser engine,
anything.

## Fix

```shi,pass
pocket_money trader {
    ticker USDC = 6;
    mint USDC = "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v";
    cap USDC = 250;
    pay USDC => ["7h44au9S2DwyKgAbsepUv459K59cEHBqE9EjSCtC15bi"];
}
```

## What each wallet gets

- **Coinbase CDP**: an account-scoped policy with `accept` rules for `signSolTransaction`
  and `sendSolTransaction`: `mintAddress`, `splValue` and `splAddress` for a token,
  `solValue` and `solAddress` for SOL. CDP accepts an operation no rule targets, so
  `typeshi allowance` says so: message signing and EVM operations stay open unless your project
  policy closes them.
- **Turnkey**: one `EFFECT_ALLOW` policy. Only the System, Token, Token-2022 and Compute Budget
  programs may appear, and every SOL transfer and SPL transfer must match a cap, a mint and a
  recipient. Everything else falls to Turnkey's implicit deny. A plain SPL `Transfer` carries no
  mint, so it is denied: the agent must use `TransferChecked`.
- **Privy**: every instruction of a Solana transaction must be allowed, so there is one `ALLOW`
  rule per kind of instruction (Compute Budget, SOL `Transfer`, SPL `TransferChecked`), for
  `signAndSendTransaction` and `signTransaction`.

Each field typeshi writes is one the vendor documents, checked against their docs on 2026-11-24.

## What it has cost

- **AIXBT, 2025-03-18: 55.5 ETH, about $106K.** An attacker reached the agent's dashboard and
  queued two prompts, and the agent sent the ETH from its wallet
  ([The Block](https://www.theblock.co/news/regulation/2025-03-18-ai-crypto-bot-aixbt-lost-eth-hack-unauthorized-dashboard-access-346911)).
  It was on Base, not Solana, so typeshi's allowance doesn't cover it today. The lesson carries
  over: nothing at the signing layer capped what one transfer could send, or limited who it could
  go to.

## What it doesn't catch

A Solana address has no checksum, so a typo that still decodes to 32 bytes is a different,
valid address, and typeshi can't tell. Copy recipients, don't type them.

The caps are per transfer. A daily total needs the wallet's own rolling limits (Privy has them;
CDP and Turnkey don't publish one yet), and an agent may still send the cap many times. The
allowance covers Solana transfers of SOL and SPL tokens; swaps and other programs are denied
rather than described. It can't stop a person who controls the wallet's admin keys from editing
the policy.
