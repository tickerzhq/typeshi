# SHI005: init_if_needed lets a second call reset an account

`init_if_needed` creates the account on the first call and accepts it as it is on every
later one. If the handler then writes it from scratch (an owner, a balance, a "claimed"
flag), a second call resets state that should only ever be set once. Anchor keeps it behind
a feature flag for this reason.

typeshi refuses it. Create the account in one instruction and change it in another.

## Example

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch drop {
    frame Claim {
        owner: Pubkey,
        claimed: bool,
    }

    cap_table Enter {
        #[account(init_if_needed, payer = ser, space = 8 + Claim::INIT_SPACE,
                  seeds = [b"claim", ser.key().as_ref()], bump)]
        claim: Account<Claim>,
        ser,
        system_program,
    }

    lock_in fn enter(ctx) -> W {
        mark_to_market!(claim.owner = per_my_last_email!(ser).key());
        mark_to_market!(claim.claimed = paper_hands);
        were_so_back!()
    }
}
```

Every call sets `claimed` back to false, so the same wallet claims again and again.

## Fix

```shi,pass
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch drop {
    frame Claim {
        owner: Pubkey,
        claimed: bool,
    }

    cap_table Enter {
        #[account(rent_free, payer = ser, space = 8 + Claim::INIT_SPACE,
                  seeds = [b"claim", ser.key().as_ref()], bump)]
        claim: Account<Claim>,
        ser,
        system_program,
    }

    lock_in fn enter(ctx) -> W {
        mark_to_market!(claim.owner = per_my_last_email!(ser).key());
        mark_to_market!(claim.claimed = paper_hands);
        were_so_back!()
    }
}
```

`rent_free` (Anchor's `init`) fails if the account already exists, so `enter` runs once per
wallet. Change the account later with `mut` in its own instruction.

## What it has cost

- **Metaplex Candy Machine v1, 2022-01-04: 3,470 machines drained, 1,027 SOL cashed out.**
  The program accepted accounts that were already initialized, so an attacker replaced their
  state (reported by an independent researcher,
  [jonlu.ca](https://jonlu.ca/posts/candy-machine); no official post-mortem found).

## What it doesn't catch

Hand-written resets: a `mut` instruction that writes an account back to its starting state
is allowed, because sometimes that is the point.
