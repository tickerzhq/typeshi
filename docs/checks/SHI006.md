# SHI006: money that comes from nowhere or goes nowhere

A program that keeps balances (a user's deposit, a pool's reserves) is a ledger, and a
ledger has one rule: every amount added to a balance came from somewhere, and every amount
taken off went somewhere. A deposit that credits a balance without taking the tokens, a
withdrawal that pays out without lowering a balance, or a fee that is charged but credited
to no one breaks it, and Rust and Anchor compile all three.

typeshi checks it for every unit you named with `ticker`. In each instruction, for each
ticker, balances must change by exactly what comes in, minus what goes out, plus what is
minted, minus what is burned:

- **balances**: `number_go_up!`, `aura_farm!` and `mark_to_market!` on a field typed with
  the ticker (`mark_to_market!(acc.field = per_my_last_email!(acc.field) - amount)` lowers
  it by `amount`);
- **in and out**: `send_it!(from => to, amount, authority)`, an SPL transfer. Signed by the
  user, it is money coming in; signed by one of the program's own accounts (one with
  `seeds`), it is money going out. `full_send!` into one of the program's accounts counts as
  money in;
- **minted and burned**: `printer_go_brrr!` and `lp_burned!`.

Amounts are read as sums of named quantities, so `amount - fee` going to one balance and
`fee` to another adds up to `amount`.

## Example

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch vault {
    ticker USDC = 6;

    frame Position {
        owner: Pubkey,
        usdc: USDC,
    }

    cap_table Deposit {
        #[account(mut, seeds = [b"position", ser.key().as_ref()], bump)]
        position: Account<Position>,
        ser,
    }

    lock_in fn deposit(ctx, amount: USDC) -> W {
        number_go_up!(position.usdc, amount);
        were_so_back!()
    }
}
```

`deposit` credits `amount` and takes nothing in: anyone can mint themselves a balance.

The other direction, paying out without lowering a balance, is the same error:

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch vault {
    ticker USDC = 6;

    frame Position {
        owner: Pubkey,
        usdc: USDC,
    }

    cap_table Withdraw {
        #[account(mut, seeds = [b"position", ser.key().as_ref()], bump)]
        position: Account<Position>,
        #[account(mut)]
        to: Account<anchor_spl::token::TokenAccount>,
        #[account(mut)]
        vault_tokens: Account<anchor_spl::token::TokenAccount>,
        /// CHECK: the vault's signer
        #[account(seeds = [b"vault"], bump)]
        vault: UncheckedAccount,
        ser,
        token_program,
    }

    // not financial advice
    lock_in fn withdraw(ctx, amount: USDC) -> W {
        send_it!(vault_tokens => to, amount, vault);
        were_so_back!()
    }
}
```

## Fix

Take the money in, and lower the balance by what goes out:

```shi,pass
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch vault {
    ticker USDC = 6;

    frame Position {
        owner: Pubkey,
        usdc: USDC,
    }

    frame Treasury {
        admin: Pubkey,
        fees: USDC,
    }

    cap_table Deposit {
        #[account(mut, seeds = [b"position", ser.key().as_ref()], bump)]
        position: Account<Position>,
        #[account(mut, public, seeds = [b"treasury"], bump)]
        treasury: Account<Treasury>,
        #[account(mut)]
        from: Account<anchor_spl::token::TokenAccount>,
        #[account(mut)]
        vault_tokens: Account<anchor_spl::token::TokenAccount>,
        ser,
        token_program,
    }

    cap_table Withdraw {
        #[account(mut, seeds = [b"position", ser.key().as_ref()], bump)]
        position: Account<Position>,
        #[account(mut)]
        to: Account<anchor_spl::token::TokenAccount>,
        #[account(mut)]
        vault_tokens: Account<anchor_spl::token::TokenAccount>,
        /// CHECK: the vault's signer
        #[account(seeds = [b"vault"], bump)]
        vault: UncheckedAccount,
        ser,
        token_program,
    }

    // not financial advice
    lock_in fn deposit(ctx, amount: USDC, fee: USDC) -> W {
        send_it!(from => vault_tokens, amount, ser);
        number_go_up!(position.usdc, amount - fee);
        number_go_up!(treasury.fees, fee);
        were_so_back!()
    }

    // not financial advice
    lock_in fn withdraw(ctx, amount: USDC) -> W {
        mark_to_market!(position.usdc = per_my_last_email!(position.usdc) - amount);
        send_it!(vault_tokens => to, amount, vault);
        were_so_back!()
    }
}
```

When an instruction really does create or destroy balance (a reward, interest, a
write-off), mark it `#[printer_go_brrr]`: typeshi skips the check for that fn and leaves the
word in the source for the next reader.

## Why it matters

Move, the language Sui and Aptos use, makes a coin impossible to copy or drop by mistake:
its type system won't allow it. Solana programs keep their balances in plain integers, so
nothing stops a deposit from crediting money that never arrived. This is the same guarantee
for the balances a Solana program keeps, checked when it compiles.

## What it doesn't catch

Only changes at the top of an instruction are followed: a balance changed inside a branch
(`bull ... bear`) or a loop is not checked. A transfer whose amount has no ticker turns the
check off for that instruction, so give amounts a ticker. A balance set outright
(`acc.field = x`) on an account that already exists can't be followed either. Transfers
written by hand in Rust are invisible to it; use `send_it!`. And it checks that amounts add
up, not that the price used in a swap is fair.
