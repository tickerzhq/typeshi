# SHI002: two different money units in one sum, comparison or write

A money amount has a unit: which asset it is, and how many decimals its smallest unit has.
USDC has 6, SOL has 9, ETH has 18. In Rust and Anchor they are all a `u64`, so adding
USDC to SOL compiles, runs, and is off by a factor of 1,000. Writing a cbETH/ETH ratio
where a cbETH/USD price belongs compiles too.

typeshi gives each unit a name with `ticker`, and refuses to add, subtract, compare or
write two different ones:

```text
ticker USDC = 6;
ticker SOL = 9;
```

A ticker is a plain `u64` in the Rust typeshi writes (`pub type USDC = u64;`, plus
`USDC_DECIMALS`), so it costs nothing at run time. Prices are tickers too: a USD price of
cbETH with 8 decimals is `ticker CBETH_USD = 8;`.

## Example

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch vault {
    ticker USDC = 6;
    ticker SOL = 9;

    frame Vault {
        cabal: Pubkey,
        usdc: USDC,
    }

    cap_table Deposit {
        #[account(mut, has_one = cabal)]
        vault: Account<Vault>,
        cabal,
    }

    lock_in fn deposit(ctx, amount: SOL) -> W {
        mark_to_market!(vault.usdc = per_my_last_email!(vault.usdc) + amount);
        were_so_back!()
    }
}
```

`amount` is SOL and `vault.usdc` is USDC. One SOL deposited would credit 1,000 USDC.

The same check catches a price written in the wrong unit, the bug behind Moonwell's loss:

```shi,fail
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch market {
    ticker CBETH_ETH = 18;
    ticker CBETH_USD = 8;

    frame Market {
        cabal: Pubkey,
        cbeth_price: CBETH_USD,
    }

    cap_table SetPrice {
        #[account(mut, has_one = cabal)]
        market: Account<Market>,
        cabal,
    }

    lock_in fn set_price(ctx, ratio: CBETH_ETH) -> W {
        mark_to_market!(market.cbeth_price = ratio);
        were_so_back!()
    }
}
```

## Fix

Convert with a price before you mix. Multiplying or dividing (`*`, `/`) is how a
conversion is written, so the result carries no unit until you give it one:

```shi,pass
gm!("7PxhmDuhhe394QJgKyW1P7Ce4dPCfFPN2yKq4KCCj7Vj");

stealth_launch vault {
    ticker USDC = 6;
    ticker SOL = 9;

    frame Vault {
        cabal: Pubkey,
        cap: USDC,
    }

    cap_table Quote {
        #[account(has_one = cabal)]
        vault: Account<Vault>,
        cabal,
    }

    ape fn quote(ctx, amount: SOL, usdc_per_sol: u64) -> W {
        let value: USDC = amount * usdc_per_sol / 1_000_000_000;
        trust_me_bro!(value <= per_my_last_email!(vault.cap), "over the cap");
        were_so_back!()
    }
}
```

When you really mean to move a raw number from one unit to another, say so with `as u64`;
typeshi treats the result as unitless, and the next reader can see you meant it.

## What it has cost

- **Moonwell, 2026-02-15: $1.78M of bad debt.** The oracle "used only the raw cbETH/ETH
  exchange rate" instead of multiplying by ETH/USD, so cbETH was priced at about $1.12
  instead of about $2,200 and liquidators took the collateral
  ([Moonwell's incident summary](https://forum.moonwell.fi/t/mip-x43-cbeth-oracle-incident-summary/2068)).

## What it doesn't catch

typeshi follows units through account fields (`vault.usdc`), typed params and `let`
bindings, `+`, `-`, comparisons, writes, `number_go_up!` and the `checked_`, `saturating_`
and `wrapping_` add and subtract methods. It does not check that a conversion uses the
right price, follow units through helper functions, or know a field's unit unless you
gave it a ticker. Everything typed `u64` stays unchecked.
